# Development guardrails

- Never commit real credentials, temporary API entrypoints, local secret files, or machine-specific paths. Public examples must use placeholders and fake keys.
- Streamlit Ollama credentials belong only to the current session. Inject them explicitly into a new client for checks and answers. Never mutate process environment variables or cache clients carrying credentials across sessions.
- Keep secrets out of public Settings, repr, logs, exception messages, downloads, and evaluation results. Preserve endpoint and local-path export redaction, including upstream responses that echo connection details.
- Credential-bearing remote connections require HTTPS; literal localhost and loopback addresses may use HTTP. Reject URL credentials and never forward authorization through redirects.
- Test with fake credentials and mock HTTP services only. Never read personal secrets or call real paid services from tests.
- Preserve CLI/environment compatibility and Cloudflare Claude support. Keep provider=ollama for both local and remote connections. Connection UI work must not change inference limits, server rate limits or stream=false. The only System 1 flow exception is the greeting fast path below; other changes to what System 1 reads or sends need explicit authorization.
- The remote Streamlit model is developer-controlled by REMOTE_OLLAMA_MODEL in tronclass/config.py, the sole runtime source. Display it read-only with no remote model input or selector. Connection checks must verify that exact model exists and fail clearly without fallback. Keep local Ollama and Cloudflare model controls. Do not add model restrictions to the API gateway.
- Add regression tests before implementation. Validate changes with the full pytest suite, evaluation dry-run, and git diff --check; inspect staged changes for sensitive data before committing.

- Ollama output budgets are optional: by default omit max_tokens, retain explicit positive caps, and report finish_reason=length as incomplete. Do not reintroduce a hidden default cap or automatic retry/continuation loops. Cloudflare Claude retains a positive required budget. Preserve this distinction in UI, CLI, tests and export metadata.

- Greeting fast path: only an opening message (empty history) made entirely of words in system1.GREETINGS gets the fixed reply, without reading course data or calling a model. Keep it a deterministic word-set check — no substring matching and no LLM classification request. Mixed requests, follow-ups and anything uncertain keep the full flow with all student-visible data. Record model_called=false with usage, finish_reason and model round trip as null; never invent token usage. Extend the word set only with tests.
- Do not trade answer quality for speed: no arbitrary truncation of course data, fewer visible courses, smaller default model or shorter answers. Do not add retries, continuation loops or extra model requests to the app.
- Ollama thinking control uses only the OpenAI-compatible reasoning_effort on /v1/chat/completions: default omits it, off sends "none", on sends "medium". Do not send native /api/chat think or other services' enable_thinking on /v1, and do not hide reasoning text to simulate disabled thinking; record only reasoning_characters (null when not returned). Do not add public native Ollama routes or widen the gateway paths. Cloudflare Claude keeps no thinking setting.
- Latency evidence keeps preparation, model HTTP round trip and total separate; the round trip is not "thinking time". Missing usage or durations stay unknown. Native load/prompt_eval/eval durations are a loopback-only manual diagnostic (evaluation/latency.py --native). Model residency (OLLAMA_KEEP_ALIVE) is a setting on the machine running Ollama, not a client setting.

User operation instructions belong in README.md.
